# Что осталось в мессенджере

## Сначала исправить

- [x] Сохранять идентификатор неподтверждённой отправки при выходе из диалога. Регрессионный тест закрывает и снова открывает экран после ошибки отправки и проверяет, что повтор использует прежний ID. При полном перезапуске приложения запись в памяти теряется.
- [x] Ставить загрузку ранних сообщений в очередь, если уже идёт фоновое обновление. Регрессионный тест проверяет, что после одного нажатия загружается предыдущая страница.

## Перед публичным релизом

- [ ] Подключить мессенджер к отзывным сессиям основного приложения. Текущий API использует `X-Profile-Id`. Для этой задачи требуется общий механизм сессий и переход на него на сервере и в приложении. Проверка — после отзыва сессии чтение и отправка сообщений недоступны.
- [x] Пройти сценарий на двух Android-эмуляторах. На Android debug APK проверены отправка и прочтение, входящее сообщение в фоне и возврат в тот же диалог с ответом. Перед выпуском повторить на физических устройствах.
- [x] Измерить время загрузки списка диалогов на длинной истории. Локальный Dart API и PostgreSQL 16, 50 диалогов, по 120 HTTP-запросов к `GET /api/chats` с параллельностью 8 после прогрева. При 5 000 сообщениях p50 составил 17,9 мс, p95 — 46,7 мс. При 50 000 сообщениях p50 составил 96,9 мс, p95 — 123,9 мс. При росте истории нужно ограничить работу запроса по старым сообщениям. Пагинация одного ответа уменьшит передачу данных, а для снижения нагрузки на PostgreSQL понадобится хранить последнее сообщение и счётчик диалога отдельно.
